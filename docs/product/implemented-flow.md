# 프로젝트 2 구현 화면

## 제품과 디자인

교육 과정에서 지원 전 준비를 연습하는 웹 프로그램입니다. 기존 Python 분석의 결과 화면을 보존하고, 기능별 프론트엔드 저장소 구조로 분리했습니다. 각 팀원이 설정한 API 서버가 인증·저장·분석을 처리하며 이 저장소에는 DB나 개인 자격증명을 포함하지 않습니다. 디자인 기준은 절제된 구성(3/10), 최소 움직임(2/10), 일반 업무용 정보 밀도(5/10)입니다.

흰색 작업 화면, 녹색 주요 동작, 연녹색 분석 리포트를 유지합니다. 로그인은 푸른색의 안내 패널과 이메일 양식을 나란히 배치하고 작은 화면에서는 세로로 정렬합니다. 오른쪽 회사·공고 예시는 모두 가상입니다.

## 경로

| URL 해시 | 화면 |
| --- | --- |
| `#/login` | 소셜 공급자 / 이메일 로그인 방법 선택 |
| `#/email` | 이메일·비밀번호 로그인 |
| `#/signup` | 이름·이메일·비밀번호 회원가입 |
| `#/forgot` | 비밀번호 재설정 안내 요청 |
| `?reset_token=…#/reset` | 새 비밀번호 입력 |
| `#/resume` | 업로드·추출 확인·직접 입력 |
| `#/job` | 회사·직무·공고 본문 |
| `#/questions` | 공고에 따른 선택 답변 |
| `#/result` | 전체 모의지원 리포트 |

저장된 이력서가 없으면 공고 단계에 진입할 수 없습니다. 저장된 공고가 없으면 분석 화면을 열 수 없습니다. 리포트가 없으면 결과 경로는 질문 단계로 돌아갑니다.

## 상호작용과 접근성

- 영구 레이블, 브라우저 입력 검증, 오류 알림 `role=alert`.
- 키보드 접근, 본문 건너뛰기, 현재 단계 표시, 눈에 보이는 포커스.
- 처리 중 버튼 비활성화 및 `aria-busy`, 실패 시 입력과 재시도 보존.
- 화면 내 뒤로 이동 시 편집 값은 메모리에 보존하며, 미저장 편집 후 탭을 닫으면 브라우저 기본 안내.
- 각 단계 저장은 해당 단계의 편집만 반영합니다. 다른 단계의 미저장 이력서·공고 편집은 유지하며, 저장된 분석 입력이 달라지면 이전 질문의 답변 편집은 초기화합니다. 질문의 회사·공고 및 분석 결과는 저장된 서버 스냅샷을 사용하며, 미저장 이력서·공고가 있으면 안내합니다.
- 삭제 시 실제 삭제되는 데이터를 설명하고 확인.
- 이력서와 보고서 등의 동적 텍스트는 HTML 이스케이프.
- 모션 감소 설정 및 인쇄 스타일 지원.

## 검증

`node --test tests/unit/*.test.mjs`는 HTML 이스케이프, 결과 카드 식별자와 근거 표시, 미설정 OAuth 비활성화, 비밀번호 재설정 후 CSRF 갱신, 저장된 분석 맥락과 단계별 미저장 편집 보존·초기화를 검사합니다. `python -m unittest discover -s tests -p test_server.py`는 API 주소 검증, 오류 상태, 프록시 헤더·쿠키·리디렉션·설정 읽기를 외부 연결 없이 검사합니다. 각 팀의 실제 DB/API 연결 후 회원가입부터 업로드·모의지원까지 별도 통합 검증이 필요합니다.
