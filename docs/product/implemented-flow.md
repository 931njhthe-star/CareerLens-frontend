# 구현된 사용자 흐름

## 소개에서 공고별 모의지원까지

상단 메뉴는 **소개 · 이력서 · 채용공고 · 모의 지원**입니다. 진행 단계는 메뉴와 분리된 **이력서 → 채용 공고 → 모의지원**이며, 작업 흐름 화면에만 일반 문서 흐름으로 표시합니다. 직무 선택과 관련 공고 목록은 모두 2단계입니다.

1. `#/intro`: 문서와 렌즈를 이용한 임시 소개 애니메이션을 약 2.5초 표시한 뒤 이력서 화면으로 이동합니다. 건너뛰기를 제공하며 다른 화면으로 떠나면 타이머와 이벤트를 정리합니다.
2. `#/resume`: 회원은 PDF/DOCX/TXT를 불러오고 추출 본문을 검토하거나 직접 입력합니다. 비회원도 PDF/DOCX/TXT를 첨부해 서버에 전송하고 실제 분석을 시작할 수 있습니다. 비회원 화면에는 파일명과 첨부 상태만 표시하며, 추출 본문 미리보기·직접 입력·가상 이력서 불러오기는 제공하지 않습니다. 서버는 원본 파일을 저장하지 않고 추출 내용을 임시 보관합니다.
3. `#/job`: 정해진 직무 또는 직접 입력한 희망 직무를 선택합니다. 첨부를 완료한 비회원의 선택은 임시 작업 공간에 저장합니다. 이력서 없이 직무·공고를 탐색할 수도 있지만 모의지원에는 첨부가 필요합니다.
4. `#/opportunities?role_id=...`: DB에서 관련 공고를 조회합니다. 왼쪽은 대화방 목록처럼 공고를 나열하고, 선택한 공고의 상세 내용을 오른쪽 큰 영역에 표시합니다. 양쪽은 독립 스크롤입니다. 모바일에서는 목록 위·상세 아래로 배치합니다. 이전·다음 페이지, 조회 중, 0건, 실패·재시도 상태를 제공합니다. 직무명 별칭으로 검색하며, 이력서 적합도 추천 순위를 의미하지 않습니다.
5. **이 공고로 모의지원**: 비회원도 첨부한 이력서로 공개 공고를 선택하고 진행합니다. 서버는 공고 ID로 최신 DB 원문과 접근 권한을 확인합니다. 비회원은 공개 공고만, 회원은 공개 공고와 본인의 비공개 공고만 선택할 수 있습니다.
6. `#/questions`: 선택한 공고와 저장된 이력서를 기준으로 만든 보완 질문에 선택적으로 답합니다. 공고가 바뀌면 이전 답변과 보고서는 초기화하되 이력서는 보존합니다.
7. 결과 확인: 기존 질문 위의 눈 모션 오버레이에서 최소 4초와 실제 분석 완료를 모두 기다립니다. 회원은 `/analysis`, 비회원은 `/guest/analysis`를 사용합니다. 배경 어두워짐, 눈·동공 윤곽 동시 등장, 바깥으로 자라는 방사형 황금선, 패널 순환, 마지막 폴딩은 유지합니다. 중앙 동공은 어둡게 유지합니다. 선별 진행률은 시각적 연출이며 각 선에 별도 분석 API가 있는 것은 아닙니다. 실패·취소·이탈 시 잘못 결과로 이동하지 않습니다.
8. 비회원의 `#/result`: 서버에서 실제 분석을 완료한 뒤 로그인·회원가입·직접 파기 중 하나를 선택하는 모달을 표시합니다. 배경은 정보가 없는 골격 도형을 흐리게 하고 어둡게 처리합니다. 보고서·점수·본문을 미리 받아 CSS로 가리는 방식이 아닙니다. 키보드 포커스를 모달 안에 유지하고 배경 조작을 막습니다. 첫 첨부부터 30분이라는 보관 기간과 기기 시간 기준 만료 예정 시각을 안내합니다.
9. 인증 후 `#/result`: 로그인·회원가입·OAuth를 마쳐도 동일한 비회원 자료 연결을 유지합니다. 완료된 임시 자료를 claim하면 해당 계정의 현재 작업 공간을 그 자료로 교체하고 임시 행을 삭제한 뒤 보고서를 표시합니다. 만료·삭제된 자료는 연결할 수 없어 이력서를 다시 첨부해야 합니다. 회원은 공고별 보고서를 프레임 안에서 스크롤해 읽고 **다른 공고로 모의지원**으로 같은 이력서를 다른 공고와 비교할 수 있습니다. 보고서를 볼 때는 서버에 저장한 스냅샷을 사용하고 미저장 편집을 섞지 않습니다.

## 비회원 자료의 보관과 삭제

비회원의 추출 이력서·답변·보고서는 별도 SQL `guest_workspaces` 테이블에 임시 저장합니다. 원본 업로드 파일은 디스크에 저장하지 않습니다. 게스트 응답은 첨부·공고·완료·만료 정보와 보완 질문으로 제한하며, 추출 본문·제출 답변·점수·보고서는 반환하지 않습니다.

첫 유효 업로드부터 **30분**으로 고정된 만료 시각은 파일 교체·분석·로그인으로 연장되지 않습니다. 만료 시 읽기·변경·보고서 연결을 즉시 차단합니다. 실행 중인 서버는 30초마다 만료 행을 정리하고, 시작 및 조회 시에도 정리합니다. 서버가 꺼져 있는 동안 만료된 행은 다음 시작 시 삭제합니다. 결과 확인 모달의 **이력서와 결과 파기하기**도 임시 행을 삭제합니다. 여기서 삭제는 DB 행 삭제이며 저장 장치나 외부 백업의 복구 불가능한 덮어쓰기를 뜻하지 않습니다.

## 점수와 피라미드

피라미드의 네 축은 **이력서 완성도 · 직무 적합도 · 지원 자격 충족도 · 실무 경쟁력**입니다. 사용자 요청에 따라 현재는 프론트엔드에서 임시 랜덤 점수를 만들어 **시연용 점수 · 실제 평가와 무관**이라고 표시합니다. 같은 보고서를 화면에서 다시 그릴 때는 값을 유지합니다. 서버의 기존 70/20/10 점수와 합계를 새 네 항목으로 바꾸어 표시하지 않습니다.

금색 시연 도형에서 붉은 보완 시연 도형으로 부드럽게 변합니다. 이는 변경 동작을 보여주는 예시이며 실제 개선 점수 예측이 아닙니다. 저장된 이력서와 서버 보고서는 변경하지 않습니다. 각 축의 하위 항목 3개와 제공된 참고 가중치는 표시하되 실제 하위 점수를 지어내지 않습니다. 계산식, 경력·자격 검증, 공고에 없는 조건의 처리 방식은 백엔드 담당자가 결정하고 구현할 부분입니다. 상세는 [피라미드 안내](score-pyramid.md)를 참고하세요.

## 열람과 권한

보고서는 인증과 완료 자료 연결 후 브라우저에서만 열람합니다. 인쇄 버튼과 별도 보고서 PDF 다운로드 기능은 없고, 브라우저 인쇄 CSS에서도 보고서와 비회원 결과 확인 화면을 숨깁니다. 사용자 화면 캡처, 개발자 도구, 브라우저 밖 복사를 완전히 차단하는 DRM은 아닙니다. 비회원에게 저장된 보고서를 공개하는 API는 없습니다.

회원의 업로드·직접 입력·가상 이력서 220개, 기존 `#/jobs` 카탈로그의 검색·필터·관심 저장·본인 공고 편집은 유지합니다. 기본 DB에는 가상 공고 600개가 있으며 화면에서 가상임을 표시합니다. 새 공고 목록은 실제 DB 조회 결과를 사용하므로 DB 공급 방식은 백엔드에서 교체할 수 있습니다.

이전 희망 직무 참고 기준 보고서와 `/preparation` API는 보존합니다. 새 화면에서는 선택한 채용공고로 모의지원하며, 과거 참고 기준 보고서를 새 공고 보고서인 것처럼 표시하지 않습니다.

## 연결 및 검증

현재 API 계약은 [OpenAPI 스냅샷](../../src/shared/api/openapi.json)을 기준으로 합니다. `GET /career-roles`, 공개 공고 조회와 별도 `/guest/*` 흐름이 비회원 접근을 허용합니다. 비회원 변경 요청도 익명 세션의 CSRF·Origin 검사를 적용합니다. 기존 회원 저장 API와 `/guest/claim`은 로그인이 필요합니다. 회원·비회원의 공고 선택 모두 서버 DB 원문을 사용하며 클라이언트의 공고 본문을 신뢰하지 않습니다.

핵심 검증 대상은 게스트 응답의 본문·점수·보고서 비노출, 실제 분석 완료 확인, CSRF, 공개 공고 접근 범위, 고정 만료와 DB 삭제, 인증 후 한 번의 자료 연결, 공고 변경 시 초기화입니다. 화면에서는 소개 종료·이탈 정리, 단계 표시, 결과 확인 모달의 포커스·오류·직접 파기, 만료 후 재첨부, 기존 모션·회원 편집 보존을 확인합니다. 각 팀원의 DB/API 설정 후 해당 환경에서도 검증해야 합니다.
