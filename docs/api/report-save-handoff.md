# 보고서 저장하기 연동 대기

현재 프론트는 결과 화면에 `저장하기` 버튼을 표시하지만 비활성화한다. 백엔드 코드와 DB는 변경하지 않는다.

## 확인된 현재 계약

- 기준 백엔드: `57bd0cf866b3c66a853f7c79d7cdace5faffefcf` (`develop`).
- 평가 완료 시 `analysis_reports`에 보고서가 생성된다.
- `GET /evaluations/{run_id}/result`가 보고서 ID를 제공한다.
- `GET /reports/{report_id}`는 소유권을 확인한 뒤 저장된 보고서를 조회한다.
- 사용자 의도의 별도 보관/저장, 보관 목록, 보관 취소 API는 없다.

자동 생성 기록과 사용자가 선택하는 보관 기능은 구분한다. 프론트는 저장을 가장하기 위해 localStorage에 복사하거나 다운로드를 실행하지 않는다. 시연 결과도 서버 저장으로 표시하지 않는다.

## 백엔드 담당자와 확정할 내용

1. 보고서 보관·보관 취소·보관 목록 API의 경로, 요청·응답과 권한.
2. 동일 보고서 중복 저장 처리, 이미 저장된 상태, 저장 시각.
3. `partial` 보고서의 보관 허용 여부와 삭제·보관 기간.
4. 계정 변경·세션 만료·네트워크 실패 시 상태와 오류 코드.

계약 확정 후에만 프론트 버튼을 활성화한다. 성공 응답을 받은 뒤 저장됨을 표시하고, 실패하면 재시도할 수 있게 한다. 현재 비활성 버튼은 구현된 저장 API가 있다는 의미가 아니다.
