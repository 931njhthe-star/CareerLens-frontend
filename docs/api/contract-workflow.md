# 별도 저장소의 API 명세 전달

백엔드가 API 계약의 원본을 관리하고, 프론트엔드는 승인한 명세를 자기 저장소에 복사해 버전을 고정합니다.
프론트엔드 실행과 빌드는 백엔드 저장소의 체크아웃 경로나 파일에 의존하지 않습니다.

## 현재 준비된 기능

`scripts/sync-api-contract.mjs`는 Node.js 18 이상의 내장 기능만 사용합니다.
외부 패키지나 프레임워크 설정 없이 OpenAPI JSON 파일 또는 HTTP(S) URL을 읽고 다음을 확인합니다.

- OpenAPI 3.x JSON 객체인지
- `info.version`이 지정한 버전과 정확히 일치하는지
- `paths`가 객체인지

이는 전달 파일의 최소 검증입니다. 경로별 요청·응답 스키마, `$ref` 해석, 호환성까지 검사하는 전체 OpenAPI 검증은 포함하지 않습니다.
검증에 실패하면 기존 명세와 버전 기록을 변경하지 않습니다. 검증 성공 후 임시 파일을 통해 각 파일을 교체합니다.

실제 API와 명세는 아직 없으므로 현재 `openapi.json`, `contract-lock.json`은 만들지 않았습니다.
API 클라이언트와 TypeScript 타입 생성기도 아직 구현하지 않았습니다.

## 백엔드에서 프론트엔드로 전달하는 순서

1. 백엔드에서 API 구현 시 OpenAPI JSON을 내보내고 `info.version`을 정합니다.
2. 백엔드 저장소의 릴리스 파일이나 버전별 배포 URL로 해당 JSON을 전달합니다. 기존 버전의 명세를 덮어쓰지 않고 변경 시 새 버전으로 공개합니다.
3. 프론트엔드에서 명시한 버전으로 명세를 가져옵니다. 다운로드한 JSON 파일을 수동으로 전달받는 방식도 사용할 수 있습니다.
4. 명세 diff를 검토하고 API 사용 코드와 Mock 응답을 함께 갱신합니다. 삭제·타입 변경 등 호환성을 깨는 변경은 해당 기능 수정과 함께 적용합니다.
5. `--check`로 명세와 lock이 일치하는지 확인하고 두 파일을 같은 프론트엔드 커밋에 포함합니다.
6. 실제 테스트 환경에서 API와 사용자 흐름을 검증한 후 각 저장소를 따로 릴리스합니다.

프론트엔드 저장소에서 실행하는 예시입니다. 버전과 입력 파일은 백엔드에서 전달한 실제 값으로 바꿉니다.

```powershell
node scripts/sync-api-contract.mjs --source "C:\api-contracts\openapi-0.1.0.json" --version "0.1.0"
node scripts/sync-api-contract.mjs --check
```

HTTP(S) URL은 `--source`에 전달받은 버전별 명세 URL을 입력합니다.
고정된 URL이나 API 엔드포인트는 현재 지정하지 않습니다. `--version`에 `latest` 같은 가변 별칭을 사용하는 대신 실제 `info.version`을 정확히 입력합니다.

어느 작업 디렉터리에서 실행해도 출력 위치는 스크립트가 속한 프론트엔드 저장소의 `src/shared/api`입니다.
로컬 입력 파일의 상대 경로는 명령을 실행한 현재 작업 디렉터리를 기준으로 해석합니다.
이 명령은 백엔드 저장소를 자동 탐색하거나 참조하지 않습니다.

## 저장되는 파일

| 파일 | 역할 |
| --- | --- |
| `src/shared/api/openapi.json` | 해당 프론트엔드가 사용하기로 한 명세의 JSON snapshot |
| `src/shared/api/contract-lock.json` | 명세의 `info.version`과 snapshot 파일 바이트의 SHA-256 |

입력 JSON은 들여쓰기와 마지막 줄바꿈을 통일해 저장합니다. SHA-256은 저장된 snapshot 기준이므로 원본 다운로드 파일의 해시와 다를 수 있습니다.
`--check`는 외부 파일이나 네트워크에 접근하지 않고 기존 두 파일의 최소 형식·버전·해시 일치만 검사합니다.
명세를 수동으로 바꾸면 검사에 실패하므로 백엔드에서 공개한 버전을 동기화해야 합니다.
해시는 파일 변경 여부를 확인하며, 배포자의 신원이나 실제 서버 동작을 인증하지는 않습니다.

## 프레임워크를 선택한 뒤 추가할 작업

프론트엔드 언어와 빌드 도구를 선택하면 OpenAPI 타입·클라이언트 생성기를 정하고 버전을 고정합니다.
타입·클라이언트 생성은 저장된 `openapi.json`을 입력으로 수행합니다. 다른 저장소 경로를 생성기의 입력으로 사용하지 않습니다.
이후 `--check`, 전체 OpenAPI 검증, 타입 생성, 프론트엔드 타입 검사·테스트를 CI 절차에 추가합니다.
자동 생성 결과를 커밋할지 빌드 중 생성할지도 그때 정하고, 생성 파일을 직접 수정하지 않도록 관리합니다.
